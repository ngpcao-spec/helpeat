# Validation avant ouverture du mode réel

Le projet de production est `ihuztjkblywzjdruusdj`. La création de nouveaux comptes Auth exécute actuellement `auth.on_auth_user_created`, qui appelle `private.handle_new_user()` puis `private.provision_home_user(new.id)`. La fonction crée un profil HOME Reviews, une organisation, son adhésion de propriétaire et des préférences de notification. Le même compte Google conserve le même identifiant `auth.users.id`.

Le frontend HOME Reviews charge actuellement les organisations directement. Il dépend du trigger lors du premier accès. La migration HOME Reviews `20260927191500_remove_user_provisioning_rpc` a supprimé `public.ensure_home_user()`, dont l’absence a été confirmée en production.

Les droits SQL de production permettent encore au rôle `authenticated` d’exécuter le helper historique qui accepte un UUID. Le correctif retire ce droit. Il expose une fonction publique sans argument, exécutée avec les droits du demandeur, et une fonction privilégiée dans un schéma dédié qui ne doit pas être exposé par la Data API. L’identité provient de `auth.uid()`. Une organisation déjà accessible est conservée avec les mêmes rôles. Un propriétaire dont l’adhésion a été retirée ne récupère pas cet accès automatiquement.

## Correctif à déployer dans cet ordre

Les deux fichiers SQL ci-dessous sont des migrations préparées. Ils restent hors de `supabase/migrations` tant que les vérifications requises sont incomplètes.

1. Appliquer en environnement isolé [le provisionnement sécurisé](20261124084826_home_reviews_self_provisioning.sql), puis [le patch HOME Reviews](home-reviews-onboarding.patch) préparé sur le commit `82db1a114ebcc5b4f76b72029e54b0af01b0c8c5`. Le frontend demande le provisionnement lorsqu’il ne trouve aucune organisation, puis recharge le profil et les organisations. Le trigger continue de servir les anciens clients pendant cette étape. Tester le parcours Google d’un compte restaurateur et d’un nouveau compte, le démarrage depuis une PWA installée, et le déploiement d’une mise à jour sur une ancienne installation.
2. Répéter les scénarios en environnement isolé avec [la correction du trigger](20261124082045_helpeat_auth_defer_home_review_provisioning.sql). La migration refuse de s’exécuter si la fonction publique est absente ou que ses droits sont incompatibles. Une inscription HELPEAT doit rester sans organisation. Une première ouverture de HOME Reviews doit créer exactement une organisation. Une reconnexion doit la retrouver. Après validation, appliquer en production le provisionnement sécurisé, publier le patch HOME Reviews puis vérifier sa version active avant d’appliquer la correction du trigger. En cas de régression après cette dernière étape, rétablir l’appel `perform private.provision_home_user(new.id)` dans `private.handle_new_user()`. Les droits renforcés du helper restent compatibles avec cet appel exécuté par le trigger.
3. Après ces vérifications, ajouter `https://ngpcao-spec.github.io/helpeat/?mode=real` aux URL de redirection Auth. Conserver la liste HOME Reviews, son URL principale et le client Google existant. Tester le flux PKCE dans Safari sur iPhone et iPad et dans une PWA iOS installée. HELPEAT affiche une reprise dans la fenêtre courante si le retour OAuth arrive sans sa session PKCE. [Documentation Supabase sur les redirections](https://supabase.com/docs/guides/auth/redirect-urls)
4. Tester le journal avec deux comptes Google distincts sur l’instance retenue. Vérifier la création et la modification côté A, le refus de lecture et de modification côté B, la suppression côté A et la réouverture sur deux appareils avec le même compte.
5. Autoriser le build Pages réel après ces vérifications. Le build utilise `VITE_HELPEAT_ENABLE_REAL=true` et une clé `VITE_HELPEAT_SUPABASE_PUBLISHABLE_KEY` publique. La démo reste l’URL par défaut. La reconnaissance photo, les appels IA et Web Push restent désactivés.

Les tests `npm test` vérifient l’ordre des migrations, les droits de la fonction, l’absence de doublons et la conservation des organisations et adhésions. Ils exercent aussi les politiques du journal avec deux identités fixtures. Le patch HOME Reviews ajoute un nouveau compte et un compte existant à `npm exec -- playwright test --config playwright.auth.config.ts`. Ces contrôles isolés doivent être complétés par les essais de connexion Google et de PWA sur appareils physiques.
